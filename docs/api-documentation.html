Autenticación

Las contraseñas se almacenan como hash. El registro y el inicio de sesión devuelven un token firmado. Para usar un token se debe enviar el header Authorization: Bearer TOKEN.

POST/api/auth/register

Registra un usuario. La contraseña debe tener mínimo 8 caracteres.

{
  "nombre": "Ana Pérez",
  "email": "ana@example.com",
  "password": "ClaveSegura123",
  "edad": 25
}

201 Created

{
  "usuario": {
    "id": 1,
    "nombre": "Ana Pérez",
    "email": "ana@example.com",
    "edad": 25,
    "fecha_creacion": "2026-09-24T15:30:00"
  },
  "token": "TOKEN_GENERADO"
}

Errores: 400 si faltan campos o la contraseña es corta; 409 si el email ya existe.

POST/api/auth/login

Inicia sesión con email y contraseña.

{ "email": "ana@example.com", "password": "ClaveSegura123" }

200 OK: devuelve usuario y token.

Errores: 400 si faltan datos; 401 si las credenciales son inválidas.

GET/api/auth/verify

Verifica el token de sesión.

Authorization: Bearer TOKEN_GENERADO

200 OK: devuelve el usuario. Devuelve 401 si el token falta, es inválido o expiró.

Alimentos

Todos los endpoints de alimentos reciben alimento_especifico, temperatura, rango opcional y fecha_creacion opcional. La fecha acepta DD/MM/YYYY o formato ISO.

Tabla GET POST Rango válido
alimentos_congelados /api/congelados /api/congelados -22°C a -18°C
alimentos_refrigerados /api/refrigerados /api/refrigerados 0°C a 4°C
alimentos_verduras /api/verduras /api/verduras 8°C a 12°C

POST/api/congelados 

{
  "alimento_especifico": "Pollo",
  "temperatura": -20,
  "rango": "-22°C a -18°C",
  "fecha_creacion": "24/09/2026"
}

POST/api/refrigerados 

{
  "alimento_especifico": "Leche",
  "temperatura": 3,
  "rango": "0°C a 4°C",
  "fecha_creacion": "24/09/2026"
}

POST/api/verduras 

{
  "alimento_especifico": "Lechuga",
  "temperatura": 10,
  "rango": "8°C a 12°C",
  "fecha_creacion": "24/09/2026"
}

Los POST devuelven 201 Created con id, alimento_especifico, temperatura, rango y fecha_creacion. Devuelven 400 si faltan campos, la temperatura no es numérica, está fuera del rango o la fecha no es válida.

Ejemplo de respuesta de alimento

{
  "id": 1,
  "alimento_especifico": "Pollo",
  "temperatura": -20,
  "rango": "-22°C a -18°C",
  "fecha_creacion": "2026-09-24T00:00:00"
}

Usuarios

GET/api/usuarios

Lista los usuarios. Nunca devuelve contraseñas ni hashes.

200 OK: devuelve un arreglo de usuarios.

POST/api/usuarios

Crea un usuario tradicional sin contraseña. Para usuarios que necesitan iniciar sesión, usar /api/auth/register. 

{ "nombre": "Carlos Gómez", "email": "carlos@example.com", "edad": 30 }

201 Created. Devuelve 400 si faltan nombre o email y 409 si el email ya existe.

Códigos HTTP

Código Significado

400 Datos incompletos o inválidos
